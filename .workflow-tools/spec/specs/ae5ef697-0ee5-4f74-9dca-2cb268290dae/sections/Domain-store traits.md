`memory-kernel` owns the domain-neutral `DomainStore` core trait. It represents domain identity, resolution against the selected local workspace, structured resolution diagnostics, and explicit read-only versus create/open behavior. Kernel-owned types must not depend on domain API crates, and read-only access must not initialize a store.

CRUD behavior is expressed through typed operation capabilities: `CreateEntity`, `ReadEntity`, `UpdateEntity`, and `DeleteEntity`. Each capability uses the implementing domain's existing identifiers, input/entity/patch types, result semantics, and error type. `ListEntities` is a separate optional capability with domain-specific query and result types. Domain APIs implement only capabilities matching operations they actually support; these traits do not impose a universal entity schema, fabricate unsupported operations, or remove domain-specific extensions.
