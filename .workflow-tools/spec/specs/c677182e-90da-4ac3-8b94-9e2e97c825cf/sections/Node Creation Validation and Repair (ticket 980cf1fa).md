Reject-at-creation and repair surface for behavioral workflow nodes, closing the wedge where a `validation` node could be created with a null/empty `validation_spec_id` and permanently block `session_finish`/`session_handoff` with no fix path other than adding a second required node.

- Creation validation (`session-api` `validate_workflow_node_draft`, called from `workflow_add_node`/`workflow_add_nodes`): all three gating kinds fail fast and consistently — `ticket` requires a non-empty `ticket_urn`, `spec` requires a non-empty `spec_urn`, `validation` requires a non-empty `validation_spec_id`. The batch tool (`session_workflow_add_nodes`) identifies the offending `nodes[index]`.
- Spec resolution (AC5): a `validation` node's `validation_spec_id` must resolve to a real `ValidationSpec` in the sibling `.test` store (`TestStoreConfig::get_spec`) at creation time, so a node UUID or other non-spec id cannot be passed and silently wedge finish later.
- Repair surface (`session-api` `workflow_update_node` / `workflow_remove_node`; MCP `session_workflow_update_node` / `session_workflow_remove_node`): patches or deletes a node that already exists in a persisted (possibly legacy/pre-fix) graph. A patch is re-validated with the same creation rules before it is persisted, so a repair cannot introduce a new wedge.
- Finish rejection message: when a required `validation` node is still missing `validation_spec_id` in a legacy graph, `FinishBlocked` now names the concrete repair tools (`workflow_update_node`/`session_workflow_update_node`, `workflow_remove_node`/`session_workflow_remove_node`) instead of only stating the field is missing.
- Duplicate-`node_id` no-op behavior (AC7) is documented directly on the `session_workflow_add_node`/`session_workflow_add_nodes` tool descriptions, not only in instruction files.

Validated by `memory-api/crates/session-api/src/store_tests/finish/validation_authority.rs` (creation-rejection for all three gating kinds, batch index identification, wedge repair via update and via remove, and a finish round-trip after repair) and by `cargo test -p session-api` / `cargo test -p session-mcp`.
