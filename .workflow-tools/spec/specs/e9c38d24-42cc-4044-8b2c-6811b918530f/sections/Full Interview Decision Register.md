## Normative Record

The binding source is [Ticket Schema Modernization Interview](transcripts/05-08-2026_ticketschema-state-machines/interview.md); superseded interview answers are non-normative.

- `cancelled` is a derived `verify` terminal leaf with no outgoing lifecycle edge. It is the sole direct-entry exception from any lifecycle category.
- The resolved manifest contains top-level `model_version`, `sources`, `schemas`, and `graphs`. Schema records include IDs, parent chains, hashes, resolved nodes, transitions, terminals, and type metadata. Graph records declare entity kind and schema IDs.
- Ticket, spec, and existing rule schemas reuse shared directed-lifecycle primitives but keep independent local graphs and separate type-ID namespaces. Relation edges validate declared relation-kind rules and endpoint existence only; lifecycle constraints never apply to relation edges.
- `bug` and `epic` preserve canonical IDs and upgrade in place only after global preflight. An active record is `open`, `planned`, `in-implementation`, `in-review`, or `on-hold`; it needs either a direct lifecycle route or a typed `remediation_approved_by` relation to a review ticket with an immutable approval decision. Missing proof blocks upgrade and release.
- Current manifest rules govern a transition. All records created before model-version cutover are a workflow-exempt cohort: prior history is grandfathered, checks suspend until individual migration, and the first post-migration transition follows the current model. `on-hold` restores the last non-on-hold category.
- A Track 5 research child defines deterministic rules-first classifier weights and ties for legacy `task` and `tracker-improvement`, using title, description, fields, state, and relation edges. Targets are `research`, `planning`, `implementation`, `review`, `interview`, and `testing`. Only a unique score of at least `0.80` auto-migrates; ties, lower/missing scores, and conflicting pending decisions require linked review approval with no timeout/default. Immutable evidence records classifier version, candidates, scores, rule explanation, selected target, and approval. The latest approved immutable decision is authoritative.
- Legacy `feature` conversion is deterministic: active child/dependency -> epic; unchecked acceptance criteria only -> implementation; both -> epic; neither -> archived spec.
- Track 5 writes a migration-completion record only after approved idempotent transactional batches commit.
- Track 6 begins only after Track 5 completion, blocks release on any failed validation/corrective batch, and requires an all-pass validation matrix. Corrective parts are immutable and follow the latest approved `supersedes` chain. One corrective retry is permitted; after a second failure, a human-approved remediation review is required. A rejected remediation review closes that approval path and requires a new remediation review ticket and fresh human approval before another corrective batch. Release remains blocked throughout; completed batches are never rolled back.
